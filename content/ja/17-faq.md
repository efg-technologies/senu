# 質問と比較

Senu とは何か、Axum・rmcp・Loco とどう違うか、バージョン 0.3 にできることとできないことを、短く答えます。

## Senu とは何ですか？

Senu は、一度宣言した関数を HTML ページ・JSON API・MCP ツールとして提供する、オープンソースの Rust ライブラリです。関数を、権限とパラメータと一緒に一度だけ書きます。Senu は 3 つのすべてで、同じ認証・認可・検証を同じ順序で実行し、それを証明するテストも同梱します。

## Senu は本番で使えますか？

Senu はライブラリとして公開されています。API には文書があり、セキュリティの契約はテストとして公開されています。外部のクレートから、自分の状態・認証・非同期処理を持ち込めます。0.3 からは書き込みの操作も宣言できます。一方で、監査は受けていません。0.x のクレートなので、マイナーバージョンで API が変わることがあります。自分で確かめ、自分のルートに契約テストを走らせたうえで使ってください。

## Axum だけを使うのと何が違いますか？

Senu は Axum の上に作られていて、`axum::Router` を返します。置き換えではなく、追加です。Axum はルーティングとエクストラクターを提供し、検査の順序は各ハンドラーに任せます。Senu は、宣言した操作についてその順序を固定し、書き込みには別サイトの検査を、さらに MCP の側を足し、そのすべてをテストします。アップロード、ストリーミング、WebSocket、HTML フォームには Axum だけを使い、ツールとしても提供したい操作のために Senu のルーターを合流させてください。

## rmcp だけを使うのと何が違いますか？

rmcp は MCP の公式 Rust SDK で、Senu は MCP のトランスポートに rmcp を使っています。rmcp だけを使う場合は、ツールを自分で書き、プロトコルの全体 (リソース、プロンプト、HTTP トランスポート) が手に入ります。Senu が扱う MCP の範囲は狭く、stdio 上のツールだけです。その代わり、同じ関数から各ツールに JSON ルートが、読み取りにはページも付き、権限検査は 1 つです。MCP だけで足りるとき、またはプロトコルのほかの部分が要るときは、rmcp だけを使ってください。

## Loco とは何が違いますか？

Loco は Rails 流のフルフレームワークで、ORM、マイグレーション、ジェネレーター、バックグラウンドワーカー、認証を備えています。Senu は «宣言した操作» という 1 つの考えだけを持つ小さなライブラリで、データベース層もジェネレーターもワーカーもありません。アプリケーションの全体を早く作りたいなら Loco を選んでください。すでにあるアプリケーションに、人・プログラム・アシスタント向けの一貫した読み取り口を足したいなら Senu を選んでください。

## 書き込み操作は使えますか？

はい、バージョン 0.3 から使えます。書き込みは、読み取りと同じように宣言して effect を付けます。型つきの値を持つ JSON の本文を `POST` で受け取り、認証の前に別サイトからの要求を検査し、読み取り専用の印を付けない MCP ツールとして一覧に載ります。HTML フォームの送信とファイルのアップロードは、宣言した操作では扱いません。[書き込みの操作を宣言する](/ja/writes)を読んでください。

## MCP over HTTP は使えますか？

バージョン 0.3 では使えません。MCP ツールは stdio で動き、サーバーは自分を起動したローカルのプロセスを信頼します。遠隔のトランスポートはリクエストごとの認証が必要で、別の仕様として計画しています。

## AI アシスタントは Senu のサービスを安全に呼べますか？

Senu は 3 つの点でリスクを下げます。各呼び出しは、あなたが与えた権限だけを持つプリンシパルとして走ります。テナントはアシスタントの引数からではなく、そのプリンシパルから決まります。どのツールも、読み取りだけかどうかを印で示すので、クライアントは書き込みの前に確認できます。それでも、アシスタントはそのプリンシパルに出来ることをすべて出来ます。MCP 用のプリンシパルには、仕事に足りる最小の権限を与え、書き込みの権限は本当に必要なときだけ与えてください。

## どの認証方式に対応していますか？

Bearer トークンと HTTP Basic が組み込まれています。それ以外は、`Authenticate` という 1 つのトレイトの実装です。このトレイトはリクエストのヘッダーを受け取り、プリンシパルを返します。セッション Cookie (`auth::cookie` とログイン画面への移動)、データベースの API キー、信頼できるプロキシが付けるヘッダーを、これで扱えます。[呼び出し元を認証する](/ja/authentication)を読んでください。

## データベースは必要ですか？

いいえ。状態はあなたが選ぶ任意の型で、Senu はその参照をすべての操作に渡します。データベースを使うなら、状態にプールを持たせ、操作を非同期にします。

## どの Rust のバージョンが必要ですか？

Rust 1.99 以降と、2024 エディションです。Axum 0.8、Askama 0.16、rmcp 3、Tokio 1 に依存します。

## Senu のアプリケーションはどうテストしますか？

ルートの表とツールの一覧を渡して `senu::contract::check` を呼びます。実際のリクエストを送り、«資格情報が違えば何よりも先に 401» から «別サイトからの書き込みは断る»、«JSON API と MCP ツールが同じ答えを返す» まで、12 の規則を確かめます。[契約でテストする](/ja/testing)を読んでください。

## ライセンスは何ですか？

Apache-2.0 です。コードは https://github.com/efg-technologies/senu で公開して開発しています。

## API リファレンスはどこにありますか？

https://docs.rs/senu にあります。このガイドは考え方を説明し、リファレンスはすべての型と関数を記述します。
